# 0008. Shared rig with skeleton groups and runtime retargeting

- Status: Accepted
- Date: 2026-10-09
- Deciders: project owner (PM), architect, asset-pipeline engineer, graphics engineer
- Related: spec 011 REQ-AST-003..007, REQ-AST-026, REQ-AST-027; spec 001 REQ-CMP-008, REQ-CMP-037;
  spec 002 REQ-ANA-021; spec 004 REQ-ANM-021..023; ADR-0001; architecture §2.1, §3.2, §4.8;
  rig report [`assets/reports/rig-report.md`](../../assets/reports/rig-report.md) (AC-AST-007.1)

## Context

The design assumed that the Quaternius packs (Universal Base Characters, Modular Character
Outfits - Fantasy, Universal Animation Library) share one 65-joint UE5-style skeleton with
identical bind poses, so any part could be rebound to any body and any clip played on any
character. That assumption was a third-party claim and gated M1 (architecture §7).

The M1 spike `pnpm assets:verify-rig` (`tools/verify-rig.ts`) checked every source file against the
reference `Superhero_Male_FullBody` with tolerances 0.0001 m, 0.001 rad and 0.0001 scale. Outcome:
**mapped** (report: [`assets/reports/rig-report.md`](../../assets/reports/rig-report.md)).

- Shared across all files: joint names (65), hierarchy, joint count, length axis, armature root,
  unit scale, up axis and clip targets.
- Not shared: bind/rest poses. The files fall into **four bind-pose groups**:

  | Group | Files | Max delta vs reference | Role |
  |-------|-------|------------------------|------|
  | `superhero-m` | 1 (Superhero_Male_FullBody, reference) | 0 | male body mesh |
  | `female` | 17 (Superhero_Female, female outfits, female hair and brows) | 0.107 m (6.7 % of height), 12.5° | female character skeleton |
  | `male` | 16 (male outfits, male hair and brows) | 0.034 m (2.1 %), 13.4° | male character skeleton |
  | `ual` | 2 (UAL1_Standard, UAL1_Standard_RM) | 0.064 m (4.0 %), 12.8° | clip source only |

- Male outfit parts differ from the reference mainly by a 2.37 cm thigh/leg offset without
  rotation, 2.5° at clavicles and upper arms, and up to 13.4° on thumbs; `Head`, `neck_01`,
  `spine_*`, `pelvis` and `root` are within tolerance.
- Two Female_Ranger meshes carry 5 joint influences per vertex (handled by REQ-AST-027, capped to
  4 at build).

So the rig is structurally shared but a single rest pose cannot drive all meshes and clips
unchanged. Rebinding a mesh to a skeleton whose rest differs from the mesh's bind shifts it by the
delta, and playing a clip authored on the `ual` rest on a `male` skeleton copies `ual` local
rotations and hip heights onto different bone rests.

## Decision

Keep **one rig** (`quaternius-ue5-65`) and record its bind-pose variants as **skeleton groups**;
build each character on one group and **retarget clips at runtime** onto it.

1. **Skeleton groups in the rig JSON.** `packages/parts-schema/rigs/quaternius-ue5-65.json`
   (generated by `assets:verify-rig` from `tools/rigs/*.overlay.json`) holds `skeletonGroups:
   [{id, restPose}]` (local `t`/`r`/`s` per joint), `defaultSkeletonGroup: 'superhero-m'` (the
   reference) and `parents`. Group IDs are global per rig, so parts in different packs share them.
   `assets:build` classifies each skinned part and clip into exactly one group and writes
   `PartEntry.skeletonGroup` / `ClipEntry.skeletonGroup` (REQ-AST-026). A structural difference
   fails the build (`AST_RIG_MISMATCH`); a structurally compatible file matching no group (or
   several) gets the warning `AST_SKELETON_GROUP_UNMATCHED` naming the closest group, and a clip
   then records `defaultSkeletonGroup` with `AST_CLIP_GROUP_DEFAULTED`.
2. **Character skeleton from the body.** The character's bones and rest pose come from the body's
   `characterSkeletonGroup` (authored in the pack config, slot `body` only), else the body's own
   `skeletonGroup`, else `rig.defaultSkeletonGroup` (REQ-CMP-037). The `superhero-m` body declares
   `characterSkeletonGroup: 'male'`; `superhero-f` declares `female`.
3. **Meshes keep their own inverse binds.** Every skinned mesh, including the body, is rebound by
   joint name to the character skeleton and keeps its own `boneInverses` and bind matrix
   (`composition/attach-skinned-part.ts`). No mesh is rebaked.
4. **Runtime rest-pose-corrected retargeting.** At `setClip` the clip player retargets a clip whose
   group differs from the character's (REQ-ANM-023; math in the DOM-free, three-free
   `@csg/engine/retarget`): rotations `q_t = q_tRest · q_sRest⁻¹ · q_s` (hemisphere-continuous,
   normalized); hip (`socketBones.pelvis`) and root translations
   `t_t = t_tRest + k · (t_s − t_sRest)` with `k = legLength_target / legLength_source`; other
   translation tracks dropped; scale tracks passed through. Same group or an identity plan returns
   the clip object unchanged. Results are cached per player in an LRU of 16 entries keyed
   `${clipRef}|${skeletonGroupId}` (`RETARGET_CACHE_SIZE`).
5. **`superhero-m` runs on `male`**, with or without outfits. The skeleton never changes when an
   outfit is toggled, so diff-based assembly (REQ-CMP-033) and the retarget cache stay valid.
6. **Compatibility is expressed with `bodies`, not groups.** `checkCompatibility` compares `rig`,
   `bodies` and `bodyTypes` only (REQ-CMP-008); skeleton groups are never compared. Gender pairing
   (female hair on `superhero-f`, male outfits on `superhero-m`) is authored as
   `PartEntry.bodies` in the pack configs.
7. `assets:check` re-verifies every built skinned GLB against its declared group and reports a
   non-reference group as the warning `AST_BIND_POSE_DIFFERS`, never an error.

## Consequences

- Good: the three Quaternius packs ship as planned; no fallback pack and no per-pack bone maps.
- Good: the retargeter needed for M5 user rigs exists from M1, DOM-free and unit-tested, and the
  M5 bone map plugs into `RetargetOptions.boneMap` without changing `retargetTracks`.
- Good: clip bytes stay single-copy (one `ual` set for every character), keeping the default set
  at 3.74 MB against the 15 MB budget.
- Bad: **small seams on `superhero-m` worn alone.** Its mesh is deformed by its bind delta to
  `male`: thighs offset about 2.4 cm, shoulders 2.5°, thumbs up to 13.4°; roughly 2 px at a 128 px
  sprite, slight hip/shoulder stretch, no tearing. With outfits the visible body (head) has zero
  delta.
- Bad: **residual shear on bones with rotated rests** when anatomy scales them: anatomy's
  diagonal-scale child compensation leaves about 0.5–0.7 % shear (accepted for M1, spec 002).
  This is an anatomy limitation that the per-group rests make visible, not a retarget error.
- Bad: **retargeted clips interpolate linearly.** `tracksToClip` builds linear tracks, so STEP keys
  in a source clip become interpolated after retargeting; cubic-spline tracks cannot be
  retargeted and fail as `ANM_CLIP_LOAD_FAILED` (`reason: 'parse'`). Clips of the character's own
  group are not rebuilt and keep their interpolation.
- Bad: local-space retargeting preserves motion relative to each bone's rest, not world
  directions; with ≤ 2.5° limb deltas the difference shows only on fingers and thumbs. World-space
  and A/T-pose correction stay M5 (REQ-UPL-022/023).
- Bad: female head parts do not fit male bodies (about 5 cm / 8° head delta). They are filtered by
  `bodies`; a head-only rest correction is a possible M3/M5 follow-up.
- Risks: a future pack adding a fifth bind pose needs only an overlay entry and a rerun of
  `assets:verify-rig`; the 4-group rig JSON is about 55 KB per manifest (≈ 12 KB gzip). If the
  `superhero-m` seams are unacceptable in M2 goldens, the fallback is a leg-only build-time rebake
  of that one mesh, tracked as a follow-up.

## Alternatives considered

- **Rebake meshes at build time to one bind pose.** At rest it produces the same vertices as
  runtime rebinding with own inverse binds (both apply the bind delta by linear blend skinning), so
  it adds tooling for no visible gain, and it would still need a clip retarget. Rejected; kept only
  as the leg-only fallback for `superhero-m`.
- **Pre-bake retargeted clips per character group at build time.** Doubles clip bytes (43 UAL clips
  × 2 character groups) against the 15 MB default-set budget, ties clips to built-in skeletons, and
  cannot serve M5 user rigs, which need the runtime retargeter anyway. Rejected.
- **Switch the character skeleton to `superhero-m` when no outfit is worn.** Removes the seams but
  changes the skeleton on every outfit toggle, breaking diff-based assembly and forcing anatomy
  and clip-cache rebuilds. Rejected.
- **Make skeleton groups a compatibility rule** (a skinned part fits only a body of the same
  group). The group mismatch is harmless at runtime because of own inverse binds, and `bodies`
  expresses the real constraint (gendered fit) directly. Rejected.
- **KayKit Adventurers fallback pack.** The pre-agreed fallback if the Quaternius rigs were
  unusable. Not needed: names and hierarchy are shared, and the bind-pose differences are
  handled by groups plus retargeting. Rejected.
