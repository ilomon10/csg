# packages/parts-schema and pack manifest rules

Specs: 001 (CMP, `CharacterSpec`), 002 (ANA), 003 (PIX, `RenderSettings`), 004 (ANM, `ClipManifest`), 005 (EXP, `ExportSettings`), 008 (UPL, `UserAssetRecord`), 011 (AST, manifests). GEN-008 in `specs/000-overview.md`.

## Pack manifests (spec 011)

- Authored fields live in `tools/packs/<packId>/pack.config.json`: `id`, `name`, `slot`, `match`, `hides`, `tintSlots`, `alsoOccupies`, `bodyType(s)`, `tags`, `socket`, `license`.
- `assets/packs/<packId>/manifest.json` and `clips.json` are generated by `pnpm assets:build`. Never hand-edit them. Computed fields are `file`, `rig`, `sha256`, `stats`, `durationSec`, `hasRootMotion` and `thumbnail`.
- `pnpm assets:check` fails with `AST_MANIFEST_STALE` when a manifest differs from its build output, and tells you to edit `pack.config.json` instead.
- `pnpm assets:verify-rig` checks each skinned part and clip against its `RigDefinition`.
- Removed part or clip IDs go in `assets/packs/<packId>/retired-ids.json` (`AST_ID_REMOVED`). Retired IDs are never reused (`AST_ID_REUSED`).

## Schema rules

- Depend on `zod` only. No `three`, no React, no DOM APIs, no other `@csg/*` package.
- Every persisted document has `format` and an integer `version`. Derive the TypeScript types with `z.infer` from the Zod schema.
- Migrations are pure `vN -> vN+1` functions that run before validation. Never write an older version back.
- A version bump needs a migration and a fixture test built from the previous version.
- Every part needs a license, an author and a source URL. Validation names the entry ID and the missing field (AC-GEN-008.1).
- Part, slot, socket and tint IDs are stable. Never reuse an ID, even after a part is removed.
- Manifests describe data only. New parts and palettes are data, not engine code (P-11).
- Test with small in-code fixtures. Name tests after ACs, for example `it('AC-GEN-008.1: ...')`.
- Verify with `pnpm exec vitest run packages/parts-schema`.
